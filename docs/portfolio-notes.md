# 포트폴리오 기획 노트

## 핵심 주제

AI를 단순히 코드 생성 도구로 사용하는 것이 아니라, 개발자가 문제를 이해하고 구조를 설계한 뒤 AI를 지휘하는 방식으로 활용한다.

## 넣고 싶은 내용

1. AI를 활용하는 법
2. AI를 잘 활용하는 법
3. 나만의 개인 기술 위키와 개발 플레이북을 만들고 관리하는 과정
4. 과거 프로젝트에서 AI를 활용하며 구조를 개선한 경험

## 현재 생각

AI를 잘 활용하려면 일을 잘 시킬 수 있어야 한다. 일을 잘 시키려면 개발자가 무엇을 시켜야 하는지 알아야 한다.

그렇다고 모든 코드를 손으로 완벽하게 구현할 수 있을 정도로 외워야 한다는 뜻은 아니다. 중요한 것은 상황별로 어떤 알고리즘, 패턴, 기술, 구조가 필요한지 판단하고 AI에게 정확히 지시할 수 있는 폭넓은 지식이다.

즉 AI 시대의 개발자는 단순히 코드를 많이 치는 사람이 아니라, 문제를 파악하고 방향을 정하는 지휘관에 가까워진다.

## 표현 후보

`라이브러리`라는 표현은 코드 묶음처럼 들릴 수 있어서 포트폴리오에서는 더 넓은 의미를 가진 표현이 좋다.

- 개발 플레이북
- 기술 노트
- 패턴 라이브러리
- 개인 기술 위키
- 문제 해결 레퍼런스
- AI 지시용 지식 베이스

현재 가장 마음에 드는 표현은 `개인 기술 위키`다. 포트폴리오용 표현을 넘어서, 실제 개발 중 바로 꺼내 쓰는 핵심 지식 저장소라는 의미가 있다.

문서 성격은 둘로 나눈다.

- `개인 기술 위키`: 프로젝트 중 바로 보는 핵심 규칙, 구조, 프롬프트만 담는다.
- `개발 플레이북`: 왜 그런 판단을 했는지, 어떤 실패와 회고가 있었는지, 긴 사례 설명을 담는다.

## 포트폴리오에 넣을 핵심 문장 후보

AI에게 코드를 대신 쓰게 하는 데서 멈추지 않고, 문제를 이해하고 구조를 설계한 뒤 적절한 지시를 통해 결과물을 개선하는 개발 방식을 추구합니다.

AI를 잘 활용하기 위해 알고리즘, 아키텍처, 디자인 패턴, 기술 선택 기준을 정리한 개인 기술 위키를 만들고 있습니다.

프로젝트 과정에서 AI가 만든 구조를 그대로 사용하지 않고, 팀원과 논의하며 아키텍처를 조정하고 유지보수하기 좋은 형태로 개선한 경험이 있습니다.
